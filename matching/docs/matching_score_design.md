# Soulink 匹配评分系统设计文档

## 1. 整体架构

```
输入: N 份问卷回答
  ↓
Step 1: 数据预处理
  - 过滤未完成 / 未参与的问卷 (completed=true & participating=true)
  - 数据类型标准化
  ↓
Step 2: 池子分配 (Pool Assignment)
  - 根据 Q1(我的性别) + Q2(希望匹配的性别) 分池
  - 输出: 男女池、男男池、女女池
  ↓
Step 3: 硬性筛选 (Hard Filters)
  - 年龄范围互通检查 (Q7 ↔ Q8)
  - 身高范围互通检查 (Q9 ↔ Q10)
  - 不通过 → 该配对直接排除
  ↓
Step 4: 兼容性评分 (Compatibility Scoring)
  - 对每一对候选 (A, B):
    - 计算 score(A→B): A 对 B 的偏好得分
    - 计算 score(B→A): B 对 A 的偏好得分
  ↓
Step 5: 偏好列表构建
  - 每人按得分对所有候选人排序
  ↓
Step 6: 匹配算法
  - 男女池 → Gale-Shapley
  - 男男池 → Irving 稳定室友算法
  - 女女池 → Irving 稳定室友算法
  ↓
Step 7: 结果输出与质量评估
```

## 2. 池子分配 (Pool Assignment)

### 2.1 基本规则

| A 的性别 (Q1) | A 希望匹配 (Q2) | B 的性别 (Q1) | B 希望匹配 (Q2) | 池子 |
|---|---|---|---|---|
| 男 | 女 | 女 | 男 | 男女 |
| 男 | 男 | 男 | 男 | 男男 |
| 女 | 女 | 女 | 女 | 女女 |
| 男 | 非二元 | 非二元 | 男 | 男女 (广义) |
| 女 | 非二元 | 非二元 | 女 | 女女 (广义) |
| 非二元 | 非二元 | 非二元 | 非二元 | 特殊池 |

### 2.2 配对可行性判定

两个人 A 和 B 可以进入同一池子，当且仅当：

```
A.Q2 == B.Q1  AND  B.Q2 == A.Q1
```

即 A 想要的性别恰好是 B 的性别，且 B 想要的性别恰好是 A 的性别。

### 2.3 非二元性别处理

选择「非二元性别」的用户可能同时出现在多个池子中。建议将非二元性别用户视作可匹配任何性别，但需满足双向偏好一致。

## 3. 硬性筛选 (Hard Filters)

硬性筛选是 **二元判定**：通过则继续评分，不通过则该配对直接排除。

### 3.1 年龄互通 (Q7 ↔ Q8)

```
pass_age(A, B) =
    A.Q7 ∈ [B.Q8.min, B.Q8.max]   // A 的年龄在 B 的接受范围内
    AND
    B.Q7 ∈ [A.Q8.min, A.Q8.max]   // B 的年龄在 A 的接受范围内
```

若 Q8 标记 `unlimited: true`，视为不限制。

### 3.2 身高互通 (Q9 ↔ Q10)

```
pass_height(A, B) =
    A.Q9 ∈ [B.Q10.min, B.Q10.max]
    AND
    B.Q9 ∈ [A.Q10.min, A.Q10.max]
```

### 3.3 吸烟硬性否决 (Q29 ↔ Q30)

当一方吸烟频率高且另一方容忍度极低时，视为硬性不兼容：

```
smoking_intensity(Q29) = { 从不: 0, 偶尔: 3, 经常: 6 }

veto_smoking(A, B) =
    (smoking_intensity(A.Q29) >= 3  AND  B.Q30 <= 2)
    OR
    (smoking_intensity(B.Q29) >= 3  AND  A.Q30 <= 2)
```

若触发 → 该配对被排除。

## 4. 兼容性评分系统

### 4.1 评分总公式

对于一对 (A, B)，A 对 B 的偏好得分为：

```
score(A→B) = Σ_d ( W_d × S_d(A, B) )
```

其中 `d` 是评分维度，`W_d` 是维度权重，`S_d` 是维度得分 (0~1)。

每个维度内部由若干题目组成：

```
S_d(A, B) = Σ_q ( w_q × imp(A, q) × s_q(A, B) ) / Σ_q ( w_q × imp(A, q) )
```

其中 `imp(A, q)` 是 A 对题目 q 的重要性加权。

### 4.2 重要性加权 (Importance Modifier)

每道题有一个 `importance` 布尔标记（"对我更重要"）。

```
imp(person, q) = {
    IMPORTANCE_MULTIPLIER  if person.q_importance == true
    1.0                    otherwise
}
```

建议 `IMPORTANCE_MULTIPLIER = 1.8`。

效果：当用户标记某题为重要时，该题在其偏好得分中的权重放大 1.8 倍；如果该题不匹配，对其总分的惩罚也更大。

### 4.3 基础评分函数

#### 4.3.1 量表相似度 (Likert Similarity)

用于 7 点量表题，衡量两人回答的接近程度：

```
likert_sim(a, b) = 1 - |a - b| / 6
```

范围：[0, 1]。完全一致 = 1.0，极端不同 (1 vs 7) = 0.0。

#### 4.3.2 量表互补度 (Likert Complementarity)

用于照顾角色等适合互补的维度（a + b ≈ 8 时最佳）：

```
likert_comp(a, b) = 1 - |a + b - 8| / 6
```

#### 4.3.3 多选集合交叉 (Jaccard Similarity)

用于兴趣、特质等多选题：

```
jaccard(A_set, B_set) = |A_set ∩ B_set| / |A_set ∪ B_set|
```

#### 4.3.4 多选交叉匹配 (Cross-Match Ratio)

用于「我想要的 ↔ 对方拥有的」交叉题（如 Q17 ↔ Q18）：

```
cross_match(want_set, offer_set) = |want_set ∩ offer_set| / |want_set|
```

衡量：A 想要的特质中，B 能提供多少比例。

#### 4.3.5 单选类别匹配 (Categorical Match)

用于有序单选题，通过预定义的兼容矩阵或距离函数：

```
cat_match(a, b, matrix) = matrix[a][b]   // 值域 [0, 1]
```

#### Q29 ↔ Q30 — 吸烟交叉 ⭐

已通过硬性筛选（极端不兼容已排除），这里计算软分数：

```
smoking_score(A→B) = {
    1.0                                              if A.Q29 == 从不
    B.Q30 / 7                                        if A.Q29 == 偶尔
    B.Q30 / 7                                        if A.Q29 == 经常
}

// score(A→B) 使用 smoking_score(B→A): B 对 A 的吸烟接受度
// 这里实际衡量的是: B 能否接受 A 的吸烟状态
```

注意方向：计算 `score(A→B)` 时无需考虑 A 对 B 的吸烟接受度（那是 A 的偏好，已在 `score(A→B)` 中通过 B 的吸烟状态来衡量）。

更精确地：
```
s_smoking(A→B):
  // A 能否接受 B 的吸烟状态
  if B.Q29 == 从不: 1.0
  if B.Q29 == 偶尔: A.Q30 / 7
  if B.Q29 == 经常: A.Q30 / 7
```

权重：`w = 0.12`

### D5: 兴趣爱好 (W = 0.10)

#### Q32 — 兴趣（多选）

```
s_Q32 = jaccard(A.Q32, B.Q32)
```

#### Q33 — 希望的兴趣重合度（量表）

Q33 影响 D5 整体权重的调制：

```
interest_desire = (A.Q33 + B.Q33) / 14   // 0~1，双方对重合度的共同期望

S_D5 = s_Q32 * interest_desire + s_Q32 * (1 - interest_desire) * 0.5
```

简化为：
```
S_D5 = s_Q32 * (0.5 + 0.5 * interest_desire)
```

当双方都不在乎兴趣重合（Q33 都为 1），S_D5 ≈ 0.5 * s_Q32（即使兴趣不同也只有微弱惩罚）。当双方都非常在乎（Q33 都为 7），S_D5 ≈ s_Q32（兴趣重合度直接决定分数）。

```
                        Q43 选项
                    主动找话题  记住细节  安排见面  直接表达  默默付出  分享生活
Q42    稳定回复      0.8       0.5      0.3      0.2      0.4      0.3

       尊重边界      0.2       0.6      0.2      0.2      0.5      0.3
```

```
s_Q42_Q43(A→B) = max mapping score between A's Q42 selections and B's Q43 selections

具体算法：
  对 A 选择的每个 Q42 项:
    找到 B 的 Q43 选项中与之映射得分最高的
  取所有 Q42 项对应最高分的平均值
```

#### Q52 — 底线检查（多选）⚠️ 惩罚机制

由于 Q52 的选项是抽象的价值观底线（如"不真诚"、"不忠诚"），无法直接从问卷中判断对方是否符合。但可以做 **底线共识度** 检查：

```
s_Q52 = jaccard(A.Q52, B.Q52)   // 底线共识度 — 看重相同底线的人更兼容
```

权重：`w = 0.12`

## 6. 最终得分汇总

### 6.1 维度得分

```
score(A→B) = 0.08 × S_D1(A,B) +
             0.07 × S_D2(A,B) +
             0.15 × S_D3(A→B) +   // 含非对称交叉匹配
             0.20 × S_D4(A→B) +   // 含吸烟交叉
             0.10 × S_D5(A,B) +
             0.20 × S_D6(A→B) +   // 含 Q42↔Q43 交叉
             0.20 × S_D7(A→B)     // 含 Q45↔Q44 交叉
```

得分范围：[0, 1]，可映射为百分制。

### 6.2 非对称性说明

以下维度中 `score(A→B) ≠ score(B→A)`，因为交叉匹配和重要性标记不同：

| 非对称来源 | 影响维度 |
|---|---|
| Q17↔Q18 特质交叉 | D3 |
| Q29↔Q30 吸烟交叉 | D4 |
| Q42↔Q43 安全感交叉 | D6 |
| Q45↔Q44 事业心交叉 | D7 |
| importance 标记不同 | 所有维度 |

这种非对称性是 **有意设计的**：在 Gale-Shapley 中，每个人的偏好排序天然就是非对称的。

### 6.3 归一化与排序

```python
for person_A in pool:
    preference_list = []
    for person_B in pool (B ≠ A):
        s = score(A→B)
        preference_list.append((B, s))
    preference_list.sort(key=lambda x: -x[1])  # 降序
    A.preferences = [b for b, s in preference_list]
```

## 7. 匹配算法 — 质量优先的 1:1 匹配

**核心原则：严格 1:1、质量优先、宁缺毋滥。不追求每个人都匹配到，只输出高质量配对。**

### 7.1 质量门控：偏好列表截断

在运行任何匹配算法之前，先对每个人的偏好列表做 **质量截断**：

```
MIN_ACCEPTABLE_SCORE = 0.40   // 可配置参数

对每个人 A:
    A.preference_list = [
        B for B in candidates
        if score(A→B) >= MIN_ACCEPTABLE_SCORE
    ]
    按 score(A→B) 降序排列
```

截断后偏好列表为空的人 → **直接标记为未匹配**，不进入算法。

这样做的效果：匹配算法只在"互相觉得还行"的候选人之间运行，自然地保证了匹配质量。

### 7.2 婚育观软否决

在计算偏好列表之前，先对原始分数施加 **全局惩罚因子**：

```
penalty = 1.0

if |A.Q47 - B.Q47| >= 5:     // 婚姻观严重分歧
    penalty *= 0.5

if |A.Q48 - B.Q48| >= 5:     // 生育观严重分歧
    penalty *= 0.5

final_score(A→B) = score(A→B) × penalty
```

婚姻和生育观同时严重分歧 → 总分打到原来的 25%，几乎必然被截断排除。

### 7.3 男女池 → 质量门控 Gale-Shapley

使用带截断偏好列表的 Gale-Shapley（又称 Gale-Shapley with incomplete lists）：

```
算法流程:
1. 每个提议者从其截断偏好列表的第一名开始提议
2. 接受者在当前持有和新提议之间选择更好的
3. 被拒绝的提议者向列表中下一位提议
4. 当提议者的列表耗尽 → 该提议者标记为未匹配
5. 从未收到任何提议的接受者 → 同样未匹配
```

**提议方选择策略**：运行两次（男方提议一次、女方提议一次），取两次结果中 `overall_quality` 更高的那个。

这与标准 Gale-Shapley 的区别在于：**列表耗尽不是异常而是常态**。任何人如果在池子里找不到足够好的匹配，就主动留空，确保最终输出的每一对都是高质量的。

### 7.4 男男/女女池 → 质量门控 Irving 稳定室友算法

使用带截断偏好列表的 Irving 算法（Stable Roommates with Incomplete Lists, SRI）：

```
Phase 1 — 提议轮:
    每人向截断列表中的第一名提议
    被提议者保留最好的，拒绝其余
    被拒绝者继续向下一位提议
    列表耗尽 → 标记未匹配

Phase 2 — 旋转消除:
    在 Phase 1 的缩减列表上执行旋转消除
    消除过程中出现空列表 → 该人未匹配
    
Phase 3 — 若 SRI 无法产出稳定匹配:
    回退到最大权匹配 (Maximum Weight Matching):
    - 构建加权图，边权 = min(score(A→B), score(B→A))
    - 移除所有边权 < MIN_ACCEPTABLE_SCORE 的边
    - 在剩余图上求最大权匹配
    - 奇数人时自然有一人未匹配
```

### 7.5 未匹配者处理

未匹配分为三种情况：

| 情况 | 原因 | 处理 |
|---|---|---|
| 截断清空 | 池内无人达到其最低可接受分数 | 标记"无合适候选" |
| 算法淘汰 | 偏好列表在算法过程中耗尽 | 标记"竞争落选" |
| 奇数落单 | 同性池人数为奇数 | 标记"名额不足" |

对所有未匹配者，输出：
- 其被截断前的 Top-3 候选及分数（供人工审核判断是否存在值得人工干预的近线配对）
- 未匹配原因标签

## 8. 质量保障

### 8.1 匹配质量指标

```
match_quality(A, B) = min(score(A→B), score(B→A))                // 短板分（双方中更弱的一侧）
match_mutual(A, B)  = (score(A→B) + score(B→A)) / 2              // 平均互评分
match_gap(A, B)     = |score(A→B) - score(B→A)|                  // 非对称落差
```

### 8.2 匹配结果分级

根据 `match_quality`（短板分）对每对匹配进行质量分级：

| 等级 | 短板分 | 含义 | 处理 |
|---|---|---|---|
| S 级 | ≥ 0.70 | 非常匹配 | 直接推送 |
| A 级 | 0.55 ~ 0.69 | 匹配良好 | 直接推送 |
| B 级 | 0.40 ~ 0.54 | 基本匹配 | 推送，附带说明 |
| 不推送 | < 0.40 | 不应出现（被截断排除） | — |

### 8.3 非对称落差预警

若 `match_gap(A, B) > 0.20`（一方觉得很好，另一方觉得一般）：

标记为「单向偏好配对」，在匹配报告中注明。不阻止推送，但作为运营参考。

### 8.4 整体统计

```
total_users       = 池内总人数
matched_users     = 已匹配人数
match_rate        = matched_users / total_users
avg_quality       = mean(match_quality for all matched pairs)
median_quality    = median(match_quality for all matched pairs)
s_rate            = fraction of matches at S level
```

## 9. 优化建议

### 9.1 婚育观软否决（已纳入主流程）

见 §7.2。Q47 婚姻观和 Q48 生育观的严重分歧（差值 ≥ 5）会导致总分被大幅压低，通常被质量截断自然排除。

### 9.2 数据质量处理

- **未完成问卷**：仅匹配 `completed=true AND participating=true` 的用户。
- **缺失值**：若某题为空，该题不参与评分，其权重重新分配给同维度其他题目。
- **异常值检测**：若用户所有量表题回答完全相同（如全选4），标记为可疑，但不排除。

### 9.3 关于池子设计的额外思考

当前的三池设计（男女、男男、女女）已经覆盖了主要场景。以下是可选的扩展：

1. **非二元性别**：若非二元性别用户数量极少，可以让他们同时进入多个池子参与匹配（需保证双向性别偏好一致）。
2. **Q3 目的预筛**：可以考虑在池子内部再按 Q3（恋爱 vs 朋友）分层。「寻找高质量新朋友」的用户与「寻找认真恋爱」的用户匹配效果可能不佳。目前通过兼容矩阵（0.2 分）自然降权，不强行隔离。

### 9.4 Gale-Shapley 双向运行

在 Gale-Shapley 中，提议方获得 **最优稳定匹配**，接受方获得 **最劣稳定匹配**。为了公平：

- 运行两次（男方提议一次、女方提议一次）
- 取两次结果中 `avg_quality` 更高的那个
- 若两次差距很小（< 0.02），优先选择 `match_rate` 更高的

### 9.5 MIN_ACCEPTABLE_SCORE 的调优

`MIN_ACCEPTABLE_SCORE` 是控制匹配率和匹配质量之间平衡的核心参数：

| 取值 | 效果 |
|---|---|
| 0.30 | 宽松，匹配率高，但可能出现低质量配对 |
| 0.40 | **推荐默认值**，平衡质量与匹配率 |
| 0.50 | 严格，匹配率低，但每对质量高 |
| 0.60 | 极严格，大量人未匹配 |

建议先用 0.40 运行一次，观察匹配率和质量分布，再决定是否调整。

### 9.6 权重可调性

上述所有维度权重应设计为 **可配置参数**。在首轮匹配后，可以收集用户反馈（是否满意匹配结果），用于微调权重分配。
