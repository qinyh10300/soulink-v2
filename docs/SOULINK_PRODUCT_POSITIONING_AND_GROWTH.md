# Soulink 产品定位与增长运营方案

> 清北校园里的跨文化 Dating 平台：先认识一个人，再决定是否更进一步。

版本：v1.0 讨论与执行稿  
日期：2026-09-24  
适用阶段：用户研究、首期内测、冷启动至首个学期  
核心用户：在清华、北大就读的国际生、交换生及有海外经历的学生；后续覆盖认同多元文化、希望认真认识新人的清北学生。

本文中的功能、预算、比例、运营时间和增长目标均为**建议或待验证假设**，不代表已经上线、已有合作、行业平均水平或效果承诺。用户范围已根据创始人的最新说明确定；市场需求仍需访谈与真实试运营验证。

## 1. 核心判断与首发决策

**建议把 Soulink 定位为：面向清北在校成年学生、从国际化学生群体切入、以双向意愿和真实见面为核心的私密 Dating 平台。**

首发卖点应当让用户一眼理解：

> 清北学生身份核验，中英双语，不必上传照片；每周少量推荐，互相愿意再聊天。

用户最先购买的是信任、合适的人和一个不尴尬的开始。AI、问卷和推荐算法是实现这些价值的方法，应放在次一级表达。

### 1.1 建议直接确定的十项选择

| 决策 | 建议 | 原因 |
| --- | --- | --- |
| 产品主线 | Dating，明确包含认真恋爱与有约会意愿的探索 | 避免用模糊交友吸引来完全不同的期待 |
| 地理范围 | 清北校内及双方可到达的周边公共场所 | 让匹配能在一周内转化为见面 |
| 首批用户 | 国际生、交换生、有海外经历的学生 | 形成可触达、可理解的初始圈层 |
| 开放原则 | 不以国籍、种族或海外经历作为优越性标签 | Diversity 是相互尊重和可参与性 |
| 核心节奏 | 每周一期 Date Drop，主动报名参加 | 把有限的人集中到同一时间窗口 |
| 推荐数量 | 默认每期一个双向候选提案；必要时一次补配 | 控制选择负担及运营复杂度 |
| 照片 | MVP 不上传照片；以后再测试可选私密照片 | 降低初期开发、审核和展示压力 |
| 交流 | 双方确认兴趣后开通站内聊天 | 用户不必一开始就交出微信 |
| 首批渠道 | 校园大使、获准的传单点位、合作社群、小红书内容 | 优先触达真实在校且愿意参与的人 |
| 首期成功定义 | 有效双向连接与双方确认的实际见面 | 注册量只能说明引流，无法说明产品成立 |

### 1.2 与现有仓库方向的关系

仓库中的 `README_CN.md`、`ROADMAP.md` 等资料包含清华校内匹配、搭子、项目伙伴、树洞及内容社区等方向。本方案按此次需求提出新的收敛建议：

- Soulink 的首发叙事聚焦清北 Dating。
- Coffee chat、散步和活动是约会的自然场景，不默认把纯交友用户放入 Dating 池。
- 项目伙伴、找 CTO、树洞、内容广场和 AI 评论暂不作为首期增长主线。
- 清北跨校能力、双语体验、现有邮箱验证对国际生的适用性，应在上线前做功能盘点；旧文档不能作为已实现的证据。
- 仓库另有 NeoLink 私密关系产品规划。建议现阶段统一 Dating 品牌与入口，避免同时运营两个相近产品、拆散同一批种子用户；若仍保留双品牌，必须明确独立定位，不能自动迁移用户关系资料。

本文件是一份产品与运营建议，不自动覆盖旧需求，也不表示已修改线上产品。

## 2. 产品定位、价值主张与边界

### 2.1 一句话定位

**中文：** Soulink 是从清北国际化学生群体出发的校园 Dating 平台，通过学生身份核验、兴趣与关系意图匹配、双向确认，帮助你低压力地认识一个值得见面的人。

**英文：** Soulink is a campus dating platform for students at Tsinghua and Peking University, starting with their international communities. Meet through shared interests, clear intentions, and mutual choice.

### 2.2 定位陈述模板

| 问题 | Soulink 的回答 |
| --- | --- |
| 为谁服务 | 18 岁及以上、当前在清北就读、愿意约会的学生 |
| 在什么情况下使用 | 社交圈固定、文化或语言有隔阂，希望认识新人却不想公开展示自己 |
| 提供什么 | 一期一次、少量、可解释、有退出空间的双向介绍 |
| 最重要的收益 | 从“想认识人”走到“愿意聊一聊、见一面” |
| 与替代方式的区别 | 校园生活半径明确、关系意图明确、照片非必需、双方确认再接触 |
| 为什么相信 | 可说明的核验方式、清楚的可见范围、可验证的运营规则、真实授权的反馈 |

### 2.3 三层价值

1. **功能价值：** 找到同一生活半径内、彼此条件兼容、当前愿意认识新人的人。
2. **情绪价值：** 不必经营精修个人主页，也不必承受主动搭讪被公开拒绝的压力。
3. **社会价值：** 跨越院系、文化背景和语言圈层，以平等的方式认识不同的人。

### 2.4 Diversity 应如何落地

“国际化”首先是体验能力，而不是海报上出现几张不同面孔：

- 核心流程、隐私说明、举报与客服至少支持中英文。
- 接受不同水平的英语和中文，不把英语流利度等同于个人吸引力。
- 用户可表达交流语言、生活方式与关系期待，也可选择不公开个人文化背景。
- 不根据国籍推断性格、性别角色、恋爱观或对亲密关系的开放程度。
- 在双方偏好兼容的前提下支持多元性别和关系对象偏好；敏感偏好只用于用户授权的匹配。
- 不默认推送跨文化对象，也不强行要求国际生和本地生互配。
- 不把“外国人”“留学生”“清北高材生”作为稀缺商品售卖，不做国籍或学校价值排名。

**推荐表述：** Different backgrounds. Mutual curiosity. A real conversation.

### 2.5 首期边界

首期只开放成年在校用户主动报名的 Dating。校友、校外社会人士、外地及海外远距离用户暂不进入同一匹配池。纯交友活动可以单独试验，但应独立报名、独立说明，不将参与者自动转成 Dating 用户。

关系意图建议只保留三个容易理解的选项：

| 意图 | 用户看到的说明 | 匹配要求 |
| --- | --- | --- |
| 希望建立认真关系 | 想逐步了解一个有长期关系可能的人 | 双方都能接受这一方向 |
| 愿意约会、慢慢了解 | 对恋爱持开放态度，先聊或见面再决定 | 不等于同意任何亲密行为 |
| 暂未确定，但明确愿意约会 | 想探索自己的期待，会诚实告知对方 | 对方必须明确接受这种不确定性 |

“只想练语言”“只找项目伙伴”“只想交普通朋友”应导向单独候补或其他服务，而不是模糊处理。

### 2.6 与用户现有选择的比较

以下比较用于形成研究问题，不代表对任何具体竞品当前功能的核实。

| 替代方式 | 用户为什么选它 | 可能未被满足的需求 | Soulink 应证明什么 |
| --- | --- | --- | --- |
| 朋友介绍 | 有熟人背书，启动自然 | 圈子有限，拒绝可能有人情压力 | 能跨圈介绍，同时让拒绝保持私密 |
| 校园群和社团 | 共同场景、真实生活联系 | 关系意图不清楚，主动表达成本高 | 参与者明确愿意约会 |
| 以照片浏览为主的产品 | 直观判断吸引力，选择较多 | 个人展示负担、生活半径与资格不确定 | 少量、可见面且无需照片的介绍也有价值 |
| 线下联谊 | 当面互动，信息丰富 | 时间成本、公开参与压力 | 可先私下表达意愿，再决定是否见面 |
| 学生自发匹配表单 | 组织快、传播简单 | 持续服务、可见范围和退出机制可能不清晰 | 能持续交付并提供稳定的隐私与支持机制 |

Soulink 不必在所有维度胜出。首期应验证的差异化组合是：**校园资格、明确 Dating 意图、照片非必需、双向确认、一期一次真实交付。**

## 3. 目标用户、需求与市场假设

### 3.1 首批用户分层

以下为研究用假设画像，不是对任何群体的性格判断。

| 用户群 | 可能的任务与困难 | 产品应验证的价值 | 可尝试触达路径 |
| --- | --- | --- | --- |
| 清北国际学位生 | 想走出固定语言圈，但不熟悉本地约会表达 | 双语说明、意图透明、生活半径可达 | 国际学生社团及其允许的活动渠道 |
| 短期交换生 | 在校时间有限，希望在本学期认识合适的人 | 在校期限兼容、快速但不催促的介绍 | 交换生组织者、迎新活动、同学邀请 |
| 有海外经历的在校生 | 希望找到能理解跨文化经历和沟通方式的人 | 共享经历与沟通方式匹配 | 交换返校社群、双语社团 |
| 认同多元文化的其他清北学生 | 想走出院系圈子，但不希望被当作语言陪练 | 平等 Dating 意图、兴趣匹配 | 兴趣社团、校园大使、校内内容 |
| 对照片展示和熟人曝光敏感的用户 | 想参与，但担心公开被看见、被评价 | 无照片参与、最小资料展示、自主暂停 | 匿名化产品演示、熟人可信推荐 |

清华公开资料列有国际学位、交换及访问学习相关项目，北大亦有国际学生项目。它们支持“存在可研究的学生群体”这一判断，但不能用于推算有约会需求的人数，更不代表任何校方合作。[清华国际学生项目](https://www.is.tsinghua.edu.cn/asdfasdf/adm/ns.htm)、[北大国际学生项目示例](https://www.isd.pku.edu.cn/cn/Uploads/Bdlb/Picture/2025/02/25/u67bd7c2c41fea.pdf)

### 3.2 用户真正要完成的任务：JTBD

访谈和功能讨论围绕具体情境展开：

> 当我发现身边总是同一群人、又希望认真认识潜在约会对象时，我想获得一次有理由、低压力的介绍，让我能决定是否继续，而不必先公开照片和联系方式。

可拆成四个任务：

1. 确认这里确实有我想认识、也可能愿意认识我的人。
2. 在保留隐私的前提下表达我的兴趣、关系期待和边界。
3. 获得双方都愿意接触的机会，而非单向曝光。
4. 从第一次开口自然推进到见面，并能体面结束。

### 3.3 最重要的待验证假设

| 假设 | 验证方式 | 失败时如何调整 |
| --- | --- | --- |
| 用户愿意明确报名 Dating | 真实招募页与访谈相互验证 | 调整表达，不能偷换成普通交友承诺 |
| 不必上传照片会降低参与门槛 | 比较资料完成率、确认率、见面率及退出原因 | 测试可选私密照片或见面前自主交换 |
| 国际化群体有足够匹配密度 | 每期计算双向条件兼容的候选数量 | 扩到认同多元文化的清北学生 |
| 每周一次比随时浏览更适合小池子 | 连续运行四期，看等待时间与重复报名 | 调整频率或滚动补配，不先做无限 Feed |
| 跨校见面可执行 | 收集双方地点、交通及入校限制反馈 | 增加校外公共场所和同校选项 |
| 中英双语能改善匹配后的交流 | 看不同语言组合的确认与对话完成情况 | 提高语言偏好权重，提供可选翻译 |

### 3.4 市场规模如何估算

暂不写未经核实的“清北数万高净值单身用户”等市场数字。采用自下而上的估算：

```text
可服务人群 = 当前就读且成年的人群中，符合实际服务范围的人
首期可触达人群 = 已获得发布许可或有真实触达能力的去重人群
有效报名 = 可触达人群 × 到达率 × 身份核验率 × 资料完成率 × 本期参与率
可形成候选提案的用户 = 有效报名中存在双向兼容候选、且本轮能够完成配对的人
```

海外经历不是必须采集的身份材料。可以通过自愿、宽泛的自我描述了解用户，不要求证明留学履历。市场估算时把国际生、交换生和有海外经历的学生去重，避免重复相加。

## 4. 设计方法：先验证什么，再做什么

### 4.1 双钻流程，压缩为两周首轮研究

| 阶段 | 要做的事 | 交付物 |
| --- | --- | --- |
| 发现，D1–D4 | 访谈 12–18 位潜在用户，覆盖两校、不同语言和在校期限 | 真实经历、放弃原因、使用替代方案 |
| 定义，D5–D6 | 提炼共性需求，区分需求、愿望与礼貌性支持 | 一页定位、三项核心假设、关键边界 |
| 探索，D7–D10 | 测试无照片卡片、可选照片卡片、匹配解释和报名页 | 2–3 套低保真原型及反馈 |
| 验证，D11–D14 | 用小规模自愿试运营跑通一次完整介绍 | 漏斗数据、失败案例、下轮取舍 |

### 4.2 访谈问题：问经历，不诱导赞同

1. 最近一次想认识潜在约会对象是什么时候？后来具体做了什么？
2. 你试过哪些方式？哪个环节让你放弃？
3. 你如何判断自己是否愿意与一个人开始聊天？
4. 陌生人看到你哪些资料，你会不舒服？
5. 你不上传照片时，愿意提供哪些信息帮助别人认识你？
6. 如果对方没有照片，你至少需要什么信息才能决定？
7. 国际化、校园身份、朋友介绍，这三者哪个真正影响你的信任？
8. 如果这学期就要离开北京，你会如何描述关系期待？
9. 收到匹配后，你最可能因为什么不回复或不见面？
10. 展示实际原型后，请对方操作，再问愿不愿参加具体的一期。

不问“你觉得这个点子是不是很好”。录音、引用和公开故事分别征得同意；拒绝公开不影响参与。

### 4.3 设计方法与实际用途

| 方法 | 在 Soulink 中的用法 | 判断标准 |
| --- | --- | --- |
| JTBD | 区分认真恋爱、探索约会、纯交友需求 | 是否解决同一类关系任务 |
| 服务蓝图 | 串联前台页面、客服、匹配排期、举报和见面反馈 | 出现异常时有明确负责人 |
| 渐进披露 | 先填必要字段，互相确认后才开放更多资料 | 用户理解每项资料给谁看 |
| 渐进承诺 | 报名、感兴趣、聊天、联系方式、见面分别确认 | 一个点击不会被解释为后续同意 |
| 隐私默认保护 | 候选范围可见、通知中性、无公开人员目录 | 默认设置即可安全参与 |
| 包容性设计 | 双语等价、性别选项可自述、敏感信息不强制公开 | 不同群体都能完成关键任务 |
| 礼宾式试验 | 在明确告知的情况下由运营辅助匹配 | 先验证价值，再增加自动化 |
| 行为漏斗分析 | 找到“看到却不注册”“匹配却不回复”的具体原因 | 改善关键转化而非只增加曝光 |

### 4.4 原型必须通过的五项任务

- 用户能在一分钟内说清平台面向谁、是否 Dating、如何收费。
- 用户知道自己尚未上传照片也能正常参与。
- 用户能在报名之前找到哪些资料会展示给候选人。
- 用户能独立完成拒绝、暂停、拉黑及举报。
- 用户知道匹配失败不代表个人价值低，也知道下一步是什么。

## 5. 核心产品体验与功能范围

### 5.1 最短用户旅程

```text
看到真实招募信息
  → 选择中文 / English
  → 阅读本期时间、资格与 Dating 说明
  → 完成年龄门槛与在校身份核验
  → 填写必要资料、关系意图和匹配偏好
  → 预览候选人将看到的资料
  → 主动报名本期 Date Drop
  → 收到一个候选提案
  → 各自私下选择是否愿意认识
  → 双方同意后开通站内聊天
  → 自愿交换照片 / 联系方式 / 提议见面
  → 各自反馈，继续、暂停或参加下一期
```

### 5.2 资料字段建议

| 信息 | 必要性 | 默认可见范围 |
| --- | --- | --- |
| 校园邮箱与核验结果 | 核验必需；邮箱不公开 | 用户与必要的受限后台；候选人只看状态 |
| 18 岁以上资格及必要年龄范围 | 进入 Dating 必需 | 候选人看用户确认的年龄展示信息 |
| 昵称、学校 | 必需 | 被推荐候选人 |
| 自我介绍、兴趣 | 简短必需，可后续补充 | 被推荐候选人 |
| 想建立的关系 | 必需 | 被推荐候选人 |
| 自我性别描述与希望认识的对象 | 只收集匹配必要部分，解释用途 | 匹配使用；自我描述是否展示由用户确认 |
| 可交流语言 | 必需，可多选 | 被推荐候选人 |
| 本期是否有时间、可接受区域 | 必需，使用粗粒度选项 | 匹配使用；约见时再交换具体安排 |
| 在校剩余时间 | 建议填写月数或学期范围 | 按用户确认展示，不公开行程 |
| 院系、年级、海外经历 | 可选 | 用户逐项选择 |
| 国籍、宗教、精确住址、资产、证件照片 | 默认不收集 | 不进入常规资料 |
| 照片、微信、手机号 | MVP 不要求 | 以后也应由用户主动逐项授权 |

学校邮箱只能证明邮箱控制权，不能独立证明年龄、当前学籍或行为可靠。需要学期复核机制；对国际生无法正常使用校园邮箱的情况，提供低留存的人工核验备选方案。邀请人担保可以辅助排查，不应替代在校资格核验。

### 5.3 首期问卷：控制在 3–5 分钟

1. 你当前希望建立什么关系？
2. 你希望认识怎样的人？哪些条件是必须满足的？
3. 你愿意用哪些语言交流？
4. 最近让你投入时间的两三个兴趣是什么？
5. 理想第一次见面：咖啡、校园散步、看展，还是其他？
6. 通常更喜欢先聊几天，还是有共同话题就见面？
7. 这周有没有见面时间？接受同校、两校或周边公共场所？
8. 还有什么希望对方提前知道的节奏或边界？此项可跳过。

人格量表、MBTI、星座可作为用户自我表达的可选话题，不能被包装为科学的恋爱成功预测。

### 5.4 推荐卡片示例

> **L · 已完成北大学生身份核验**  
> 可以用中文或英文聊天。喜欢城市散步、独立电影和自己做饭。  
> 当前期待：愿意约会，先慢慢了解。  
> 你们都希望先喝一次咖啡，并且周末有重合空闲时间。  
> 需要确认：对方预计本学期结束后离京，长期安排仍需沟通。  
> 按钮：**愿意认识 / 这次跳过**

示例人物为虚构演示。匹配理由只使用双方同意展示的信息，不通过解释间接暴露隐藏偏好。

### 5.5 双向同意与退出状态

| 状态 | 系统行为 |
| --- | --- |
| 等待双方选择 | 不公开任何一方是否先表示兴趣 |
| 一方拒绝或到期 | 向双方展示中性结束状态，不指明谁拒绝 |
| 双方愿意 | 开通匹配房间，展示双方授权资料 |
| 一方暂停或退出 | 停止新推荐；对已建立关系说明会发生什么 |
| 拉黑 | 立即停止双方联系，并排除后续再配 |
| 举报 | 保留必要证据与工单；按严重程度处理 |

“喜欢”“愿意聊天”“愿意交换照片”“愿意见面”是不同决定。照片和联系方式按持有者分别授权，不能因为对方已分享就强迫回赠。

### 5.6 功能优先级

| P0：首轮真实匹配前必须具备 | P1：跑通后改善 | P2：有证据再做 |
| --- | --- | --- |
| 两校资格核验、18+ 门槛 | 校园大使归因工具 | 更多高校 |
| 中英文核心流程 | 自愿照片分享 | 活动组织工具 |
| 必要问卷与资料预览 | 可选翻译与破冰建议 | 更复杂的个性化模型 |
| 本期报名、暂停和退出 | 见面计划卡片 | 多语言扩展 |
| 双向确认、站内聊天 | 可解释的候补与补配 | 与合适场所的商业合作 |
| 举报、拉黑、账号删除 | 自助资料修改与周期复核完善 | 有真实需求的付费服务 |
| 受限运营后台与排期 | 反馈归因和质量分析 | 独立的朋友模式 |
| 关键漏斗与权限检查 | 运营效率工具 | 其他社交场景 |

## 6. 无照片与图床照片：产品取舍

### 6.1 推荐路径

**第一阶段默认不上传照片，允许纯文字资料完成全部匹配流程；第二阶段根据真实流失原因决定是否增加可选私密照片。**

不把无照片包装成“完全不看外貌”。外貌吸引对部分用户重要，产品应给他们在继续之前自主确认的机会，而不是在见面前持续回避这个需求。

| 方案 | 优点 | 代价 | 建议 |
| --- | --- | --- | --- |
| 无照片 | 上手轻、初期审核负担低、文字兴趣更突出 | 不确定感较强，部分用户会推迟决定 | MVP 默认 |
| 任意公开图床链接 | 表面上接入快 | 失效、内容被替换、第三方访问痕迹、撤回困难 | 不作为默认正式方案 |
| 平台控制的私密存储 | 权限、删除和内容治理较可控 | 需要存储、审核和安全投入 | 有照片需求证据后的优先路线 |
| 互相确认后自行分享 | 决策由双方控制 | 平台对站外传播控制有限 | 允许但不强制，不承诺可撤回对方已保存内容 |

### 6.2 如果必须支持图床

“文件不在自己服务器上”不等于平台无需负责其展示和访问。建议明确：

- 只支持经过评估的固定服务商，避免任意外链。
- 首次导入或图片变化后重新审核，审核对象与实际展示对象一致。
- 用户知道照片由谁托管、谁可访问、删除是否覆盖源站。
- 真正的私密展示必须由服务端执行访问控制；仅隐藏页面或使用难猜 URL 不够。
- 不在邮件、社交预览卡和公开页面暴露照片地址。
- 用户撤回后停止继续展示；如外部源站不可控，不能承诺已从全网删除。

后端如需抓取外部图片，应按安全设计限制目标、协议、重定向、响应大小和网络访问范围，避免外链变成访问内部服务的入口；工程实现参考 [OWASP SSRF 防护指南](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)。

### 6.3 无照片版本如何增加吸引力

- 用三个具体生活问题替代一串抽象标签，例如“最近想拉人一起去做什么？”
- 展示真实的第一人称回答，AI 润色必须经本人确认。
- 用兴趣、关系节奏和可见面时间解释推荐理由。
- 提供“一次 30–45 分钟咖啡”的轻量约会建议，而不是要求承诺整晚。
- 在匹配后给出可选的照片交换入口，不为拒绝发照片的人降权。

## 7. 匹配机制与冷启动密度

### 7.1 优先解决“有合适的人”，再优化推荐分数

校园 Dating 的难点是双向匹配。100 个注册用户可能只有少数人同时满足对方的关系意图、对象偏好、语言、在校时间和本期参与状态。

运营不能只看总人数，也不能只看一个整体男女比例。应把用户看成节点，把“双方硬条件均兼容”看成连接，检查每位用户是否有可选对象。

```text
本期有效参与
  = 已通过资格核验 + 必要资料完整 + 主动确认本期参加 + 当前未暂停

双向兼容候选
  = 双方硬条件相互满足 + 不在拉黑/历史排除名单 + 当前可参与

覆盖率
  = 本期至少存在一个双向兼容候选的用户数 / 本期有效参与用户数
```

覆盖率不等于实际配对率：很多人都只有同一个候选时，仍无法同时完成配对。除覆盖率，还要测算**在本期一人一个候选提案的规则下，实际可覆盖多少用户**。

### 7.2 匹配顺序

1. **资格检查：** 成年、在校、正常账号、本期自愿参加。
2. **双向硬约束：** 对象偏好、明确不可接受的关系意图、语言最低条件、学校范围、可见面时间等。
3. **可解释排序：** 兴趣重合、沟通节奏、相近的关系期待、公共见面场景。
4. **整体分配：** 尽量让更多人得到合理候选，控制重复曝光，避免少数人被集中推荐。
5. **用户确认：** 只有双方愿意才建立连接。
6. **反馈更新：** 调整偏好和排期，不根据拒绝给用户打公开价值分。

硬约束与可协商偏好在问卷中分开。缺少候选时，只能请用户自愿修改条件；不能为了凑数静默放宽其边界。

### 7.3 Diversity 在匹配中如何体现

推荐可在同等基本兼容度下增加院系、经历与兴趣组合的多样性。但不强制跨国籍配对，不把群体身份变成吸引力分数，也不把用户当作其他人的“文化体验”。

跨文化只能是相互愿意的结果。真正应监测的是：不同语言用户能否顺利注册、收到合理候选、得到回复和完成见面。人数过少的群体不公开细分数据，以免重新识别个人。

### 7.4 三步建立第一批供需

**第一步：20–30 人研究与共创。** 来自多个真实圈层，分别确认需求、语言、资格核验障碍和参加时间。共创者不默认同意进入约会池。

**第二步：40–60 人受控首轮。** 在用户知情的情况下使用规则加人工辅助匹配。运营查看最小必要信息，记录每个未配上的具体原因。

**第三步：达到可交付条件后扩到 100–200 人一期。** 数字是组织规模设想，放量依据是实际可配覆盖、客服能力和前两期体验。

建议首轮放行门槛：有效参与者中至少 70% 能在当前一对一分配规则下获得兼容候选提案，并且所有候选不足者都得到清楚的候补说明。70% 是内部试验门槛，首两期后应据数据修订。

### 7.5 候选不足怎么处理

- 告知本期暂未找到合适候选，允许退出、下一期再参加或自愿修改范围。
- 下一期参与需要再次确认，不能无限默认排队。
- 给出报名和下次更新时间，避免一直显示“匹配中”。
- 优先补足稀缺的参与条件组合，例如同一交流语言、在校期限或见面区域；不要公开“缺某类人”的名单。
- 招募量大但匹配覆盖差时暂停泛流量，调整渠道结构。
- 不使用假用户、工作人员伪装成约会对象、机器人情感回复或买来的账号填池。

## 8. 品牌、界面与产品表达

### 8.1 品牌关键词

**真诚、轻松、好奇、私密、平等。**

建议统一品牌写法为 **Soulink**。若现有设计资产必须使用 SouLink，应建立统一规范，避免 SoulLink、SouLink、Soulink 并行出现在同一轮物料中。

### 8.2 文案方向

| 场景 | 中文 | 英文 |
| --- | --- | --- |
| 品牌主张 | 先认识一个人，再决定是否更进一步。 | Meet first. See where it goes. |
| 首屏解释 | 清北校园 Dating，每周一次双向介绍。 | A weekly, mutual introduction for THU & PKU students. |
| 照片原则 | 不必上传照片，也能开始认识彼此。 | No profile photo required. |
| 跨文化 | 不同背景，也可以从一次对话开始。 | Different backgrounds. A shared conversation. |
| 报名按钮 | 参加本期匹配 | Join this week's matching |
| 没有匹配 | 本期暂未找到合适的双向候选，你可以选择下一期再来。 | No suitable mutual match this round. You can opt into the next one. |

禁用效果承诺：“包脱单”“灵魂伴侣准确率 99%”“全校都在用”“清北官方婚恋平台”。“已核验”旁应说明究竟核验了什么。

### 8.3 视觉方向

- 温暖中性色为底色，一种清晰的行动色，减少夸张的婚庆或夜店风格。
- 以文字卡片、简单插画、真实获授权的校园生活场景构成视觉系统。
- 中英文信息层级一致，不能把英文压缩成小字装饰。
- 优先手机阅读；单页一个主要行动按钮，长问卷分步展示并保存进度。
- 重要信息不只依赖颜色区分，保证文字对比和可点击区域。
- 避免未经授权的校徽、官方式抬头；清楚标注由独立团队运营。

### 8.4 落地页信息顺序

1. 一句话说明是谁的 Dating 平台。
2. 三个信任点：学生资格核验、照片非必需、双方愿意再聊天。
3. 本期报名截止与结果时间，以及可能候补的说明。
4. 三步参与流程和一张明确标注虚构的示例卡。
5. 可见范围、费用、退出方式、举报与隐私入口。
6. 运营团队真实身份与可用联系渠道。
7. “参加本期”按钮。

## 9. 增长模型：集中招募与每周交付配合

### 9.1 增长的基本单位

推荐围绕**一期 Date Drop**组织活动。内容、传单、社群和校园大使共同指向同一期报名时间，匹配后再收集反馈和自愿推荐。

```text
真实校园触达
  → 本期有效参与
  → 可交付的候选提案
  → 双向连接与见面
  → 用户允许的反馈和口碑
  → 下一期更多兼容的参与者
```

将“短时批量大规模宣发”理解为：**同一时间窗口内，多个有许可的真实渠道，使用适配各自人群的内容，集中招募同一期用户。**

规模首先取决于承接能力。核心闭环没有验证时，首轮集中招募几十人通常比一口气吸引上千人更可控。

### 9.2 渠道优先级与分工

| 渠道 | 主要作用 | 初期投入 | 核心指标 | 使用条件 |
| --- | --- | --- | --- | --- |
| 校园大使与真实同学推荐 | 信任和首批有效报名 | 高 | 有效参与、双向连接质量 | 大使说明身份，不接触私人匹配资料 |
| 获准点位的传单与桌卡 | 精准触达、建立在场感 | 高 | 去重访问、有效参与成本 | 遵守场所及校内安排 |
| 合作社团及活动主办方 | 同时触达一组真实用户 | 高 | 每个渠道的有效参与及候选覆盖 | 组织者允许，用户自愿报名 |
| 微信等已有社群 | 转化、截止提醒与答疑 | 中高 | 到达报名、完成资料 | 管理员允许，少量定时发布 |
| 小红书 | 建立认知、解释产品、积累可搜索内容 | 中高 | 合格访问、品牌搜索、有效报名 | 按内容、认证、导流及广告规则执行 |
| 英文社区渠道 | 触达不常用中文内容平台的人 | 试验 | 双语流程完成率 | 先确认目标用户真实使用，不预设平台 |
| 垂直校园创作者 | 借助真实受众扩大覆盖 | 小规模试验 | 有效参与成本与后续质量 | 真实合作披露，不买虚假测评 |
| 付费信息流 | 放大已验证渠道 | 后置 | 增量获客成本及匹配效果 | 先确认行业及主体可投放资格 |

目标用户是否使用 Instagram、WhatsApp 或其他英文渠道，应由访谈与现有组织渠道确认。不要把国际生自动等同于某一平台用户。

### 9.3 归因方式

- 每个渠道、点位、素材使用不同的随机来源码。
- 来源码只代表渠道，不包含邮箱、性别、国籍或关系偏好。
- 同一用户跨渠道访问去重，记录首次来源和报名时来源，避免重复计功。
- 支持“从哪里知道我们”的可选问题，弥补跨设备及口头推荐归因。
- 校园大使只能看到汇总数量，不能看到谁报名 Dating、谁与谁匹配。
- 不把关系偏好或私密行为发给广告平台做再营销受众。

### 9.4 最值得优先尝试的三种增长组合

**组合 A：校园大使 + 双语传单 + 同一期报名。** 适合已有少量校园关系、预算有限的团队。先让 4–6 位真实大使各覆盖一个圈层，用获准点位和公开解释建立第一批参与。

**组合 B：社团协作 + 活动收尾介绍 + 公开演示。** 适合用户对隐私和产品机制有很多疑问的阶段。主办方提供介绍机会，团队用虚构资料演示，用户自己决定是否报名。

**组合 C：小红书连续解释内容 + 真实创作者体验 + 固定 Date Drop。** 适合已经有一期真实服务经验、且确认传播链路可用的阶段。内容长期可被找到，报名集中在固定时间窗口。

首月优先 A，争取 B，小规模测试 C。若校园渠道资源有限，先增加访谈和合作沟通，不用泛流量广告替代真实用户关系。

## 10. 线下传单、桌卡与校园大使

### 10.1 传单怎样才值得发

传单的任务是让目标用户在几秒内知道“为谁、做什么、何时参加、为什么可信”。首轮制作 A6 双面中英卡片，小批量验证，再增加印量。

建议先印 300–500 张，分 2–3 个获准点位测试。后续是否加印取决于有效参与成本，不以“全部发完”为成功。

**可考虑的场景：** 经允许的国际学生活动现场、双语社团活动、交换生迎新、校园周边合作咖啡店、正式开放的公告栏。具体进入、摆放和派发权限需逐一确认，不默认宿舍、食堂或校内所有空间都允许宣传。

### 10.2 可直接改日期使用的传单文案

**正面**

> **这周，认识一个你平时不会遇见的人。**  
> Soulink · 清北校园 Dating  
> 从国际生、交换生和有海外经历的同学开始，也欢迎认同多元文化的清北学生。  
> 学生身份核验 · 不必上传照片 · 双方愿意再聊天  
> 本期报名截止：[日期、北京时间]  
> 扫码了解并自愿报名：[正式报名二维码]

**背面**

> **Meet first. See where it goes.**  
> Campus dating for adult students at Tsinghua & Peking University.  
> No profile photo required. A few honest answers. Mutual interest before chat.  
> Join by [date and time, Beijing time].  
> Participation does not guarantee a match.  
> Independently operated; not an official university service.

页脚补充：仅限 18 岁及以上在校学生；本期价格或免费说明；隐私及退出入口；独立团队运营。正式印刷前，用真实手机测试二维码和完整注册流程。

### 10.3 现场十秒介绍

> “我们在做面向清北学生的校园 Dating 内测，可以不传照片，双方愿意才开聊天。这期周三截止，你可以先扫码看看说明，有兴趣再参加。”

不要在周围人能听见的情况下询问对方是否单身、喜欢什么性别或是哪国人。用户拒绝即可结束，不追问、不跟随、不要求当场注册。

### 10.4 传单实验设计

| 实验 | A 版 | B 版 | 主要观察 |
| --- | --- | --- | --- |
| 主标题 | 不必上传照片 | 每周一次双向介绍 | 到达后的有效参与率 |
| 场景表达 | 从一次咖啡开始 | 跨出熟悉的校园圈子 | 关系意图是否一致 |
| 形式 | 单张传单 | 合作场所桌卡 | 有效参与成本和维护成本 |
| 语言排布 | 中英并列 | 正面英文、背面中文 | 不同界面语言的流程完成率 |

同一轮尽量只改一个变量；点位、时间段差异要记录。样本少时报告人数和用户反馈，不因十几个点击就宣称某版本胜出。

### 10.5 校园大使机制

首轮招募 4–6 位大使作为规模设想，覆盖两校和不同真实社交圈。优先选择可信、尊重边界、愿意认真解释产品的人。

职责包括：核对可推广场景、主持公开答疑、邀请自愿参加者、收集产品困惑。大使不替用户填写关系偏好，不保管身份证件，不查看或撮合自己认识的用户私密资料。

报酬采用固定协作补贴加公开可验证的工作交付，例如完成获准点位宣传和整理匿名反馈。若设置报名激励，应设上限、去重和反作弊；不要按邀请某种性别、国籍或达成约会付酬。

## 11. 小红书内容与合作传播

### 11.1 先明确可用路径

小红书适合测试校园生活内容和产品解释，但不能假设所有婚恋交友产品都能完成认证、投放或外链导流。其官方专业号规则包含行业限制，公开规则中对涉外婚恋也有禁入表述；**本产品具体归类及可用能力需要如实提交业务说明确认，不能仅凭“校园”或“文化交流”名称推定可以开展。**[小红书专业号规则](https://ad.xiaohongshu.com/next_help/docs/195c5fe505c71b4b0335a2fe0d61d8e0)

建议把三类工作分开：

1. **自然内容：** 发布真实的校园社交观察和产品说明，逐项核对社区及账号规则。
2. **创作者合作：** 根据合作内容、披露和允许的转化方式执行，不默认等同于可投广告。
3. **付费投放：** 只有主体、品类、素材与落地链路确认可用后才做小额实验。

若平台不允许实际业务，不改名伪装为留学、语言学习或普通交友；将招募重心转向有许可的校园活动与自有报名页。

### 11.2 账号结构

建议先建立一个真实品牌账号，并支持少量真实校园共创者以各自经验发内容。团队一次准备多个不同角度的素材包，交由真实合作方自主选择和表达。

避免同一时间大量账号复制同稿、虚构体验、购买评论或私信轰炸。短时集中传播应来自渠道协作和真实参与，而不是模拟热度。

### 11.3 内容支柱与示例标题

| 内容支柱 | 示例标题 | 内容重点 |
| --- | --- | --- |
| 校园社交困境 | “认识很多人，为什么还是很难开始约会？” | 具体生活情境，不制造单身羞耻 |
| 无照片体验 | “如果不用先挑照片，你会怎么介绍自己？” | 展示虚构卡片与自我表达方法 |
| 关系意图 | “先喝杯咖啡，在你看来算约会吗？” | 讨论差异，不假定某文化的标准答案 |
| 产品透明度 | “Soulink 的互相确认，到底会公开哪些资料？” | 逐页演示可见范围和退出方式 |
| 跨文化沟通 | “同一句‘下次一起’，我们可能理解得不一样” | 邀请自愿分享，避免国籍刻板印象 |
| 创始团队日志 | “第一期校园匹配，我们会怎样处理没配上的人？” | 说明运营机制，不编造成功数据 |
| 实际体验 | “一次 40 分钟咖啡之后，我更知道自己想要什么” | 仅使用本人授权的真实经历 |
| 本期报名 | “清北校园 Dating 内测，本期报名说明” | 如实标明资格、时间、费用与不保证匹配 |

英文可测试：`Dating across cultures, on the same campus.`、`What would you write if your dating profile had no photo?`。关键词自然使用清华、北大、校园 Dating、国际学生、交换生、跨文化交友等，不堆无关热词。

### 11.4 一篇招募笔记的结构

1. 用一个具体困境开头：生活圈很近，但认识新人的入口很少。
2. 坦诚说明产品：这是有约会意愿的校园匹配内测。
3. 展示流程：报名、一次候选提案、双方确认、站内聊天。
4. 回答四个顾虑：照片、身份、熟人曝光、如何退出。
5. 给出真实的本期时间和容量依据。
6. 使用当前平台允许的报名或了解方式；不能使用变体字、暗号规避限制。

### 11.6 衡量方式与付费试验

阅读、点赞和收藏用于判断内容吸引力；核心仍是符合资格的报名及后续匹配质量。不要用泛情感话题的高阅读量证明清北获客有效。

对允许开展的付费合作，先给 2–3 位真实校园创作者小额试验预算，约定交付内容、发布时间、合作披露和素材使用范围。先验证受众是否在目标学校，不能只看粉丝数。宣传效果描述应可证明，避免夸大或编造用户规模。[小红书广告审核规范](https://ad.xiaohongshu.com/next_help/docs/8dc5bd9c45c9a90cb9912f3400d43f92)

## 12. 72 小时集中宣发与短期扩散方案

### 12.1 推荐主活动：Soulink Campus Date Drop

对外承诺应具体：**同一期报名，同一天收到结果，是否聊天由双方决定。** 不承诺一定配到人，不以虚假名额制造紧迫感。

准备阶段至少先完成一次小规模闭环验证。集中活动可选在迎新后的生活稳定期、交换生到校后或普通教学周，避开已经确认的考试高峰与长假离校期。具体校历应在每次策划时核对。

### 12.2 集中宣发前七天准备

- 确认两校报名、双语邮件、身份核验、退出和举报流程可用。
- 明确首期上限与候补政策，例如最多接收 100 名完成报名者进入候选分配评估。
- 确认可发布的社群、点位、创作者与时间段，未确认的渠道不计入计划。
- 准备中英文海报、短文、FAQ、产品演示和一页大使说明。
- 对每个渠道配置来源码，测试移动端、二维码及验证码送达。
- 列出匹配前、结果日和结果后三天的值班人员。

### 12.5 分享与推荐机制

分享公共报名页，不分享任何候选资料。初期可邀请“一位可能感兴趣的同学”，但不强制凑邀请人数解锁结果。

如设奖励，选择一次小额、明确的公共活动优惠或共创纪念物；奖励不以成功配对、提供联系方式或见面为条件。预算设上限，不诱导用户推断他人的关系偏好。

### 12.6 扩散暂停条件

出现核验大面积失败、隐私故障、举报无人处理、明显过量候补或严重渠道骚扰投诉时暂停扩散。候选分配覆盖低于试验门槛时，先补充所需参与条件或缩小本期承诺，再继续拉新。

## 13. 每周运营、活动与用户生命周期

### 13.1 推荐周节奏

所有公开时间同时标明日期与北京时间。以下是一种试运营排期，可根据课程和人员调整。

| 时间 | 用户侧 | 运营侧 |
| --- | --- | --- |
| 周一 | 开放本期报名和偏好修改 | 复盘上一期，检查核验及客服积压 |
| 周二 | 了解本期 FAQ，可参加公开答疑 | 检查有效参与、候选覆盖，补充所需渠道 |
| 周三 20:00 | 报名截止 | 冻结本期参与版本，检查退出与拉黑排除 |
| 周四 20:00 | 收到候选提案，48 小时内私下确认 | 值班答疑，处理错误与撤回 |
| 周六 20:00 | 结果确定；双方同意后进入聊天 | 关闭过期提案；符合条件者可自愿接受一次补配 |
| 周末至下周 | 自愿聊天、约见；可随时结束 | 轻量跟进，安全值班，收集独立反馈 |

不要为了严格卡点，在故障或低覆盖时仓促发放错误匹配。延期时主动说明原因、新时间和退出方法。

### 13.2 生命周期运营

| 用户状态 | 主要问题 | 推荐动作 |
| --- | --- | --- |
| 访问未注册 | 不了解资格或担心隐私 | 在页面回答问题，不追踪陌生人私信 |
| 注册未核验 | 邮件或资格流程有障碍 | 提供自助重试与人工支持；按订阅设置提醒 |
| 核验未完成资料 | 问卷太长或不理解字段 | 保存进度、解释必要性，最多一次本期提醒 |
| 完成资料未报名 | 可能暂时无时间 | 明确本期时间，由用户主动选择 |
| 已报名未配上 | 失望或怀疑自己 | 中性解释候选不足，提供下一期选择 |
| 收到提案未处理 | 没看见或不想继续 | 一次中性提醒；到期自动关闭，不公开归因 |
| 双向同意但没开口 | 不知道如何开始 | 提供三个与真实资料有关的破冰选项 |
| 已聊天未见面 | 时间或安全顾虑 | 可选的短时公共场所约见卡，不催促 |
| 见面后愿意继续 | 需求可能已满足 | 暂停新推荐，保留自主关闭和退出能力 |
| 用户不再需要服务 | 成功退出或需求消失 | 一键暂停/注销，尊重不再联系的选择 |

### 13.3 匹配后的破冰与见面

破冰问题应来自双方公开兴趣，例如：

- “你们都提到电影，有没有一部想推荐给对方？”
- “如果只有 40 分钟空闲，你更愿意喝咖啡还是走一小段路？”
- “你提到想学做一道家乡菜，哪道最值得从新手开始？”

不要依据国籍生成“你们国家的人是不是都……”一类问题。翻译或改写由用户确认后发送，AI 不代发情感承诺。

见面卡片只需要：建议时长、双方都能到达的公共地点、各自确认、取消或改期入口。跨校见面需考虑入校资格，默认提供校外公共地点选项。平台不持续收集实时定位。

### 13.4 线下活动的四种试验

| 活动 | 建议规模 | 设计 | 与 Dating 的关系 |
| --- | --- | --- | --- |
| Coffee Date Drop | 已双向确认的若干对 | 各自预约公共场所，不集中公开配对 | 主线，减少见面安排成本 |
| Conversation Night | 12–20 人 | 双语主持、小组交流、可跳过任何话题 | 明确标注是否为约会活动 |
| Walk & Talk | 8–12 人 | 公共路线、自愿同行、不强制一对一轮换 | 可作为独立报名的探索活动 |
| No-photo Profile Workshop | 10–15 人 | 帮用户用真实文字表达自己 | 共创，不默认纳入匹配 |

人数是组织建议，并非需要硬凑的名额。活动报名名单不公开；摄影单独选择；不安排“现场公开选人”“当众揭晓谁喜欢谁”。

### 13.5 社群运营

公共答疑群只承载产品规则、活动通知和参与方法，不上传问卷、身份材料或配对结果。用户加入群前应知道群成员可能看到其群昵称、头像等身份信息；不进群仍可使用产品。

适合长期维护的是校园大使工作群和共创反馈群。不要把全体 Dating 用户拉进一个大群，让隐私成本随着增长一起增加。

### 13.6 反馈与成功退出

每次连接只问少量可选问题：是否开始交流、是否实际见面、是否愿意继续、哪里不舒服。双方各自提交，非必要不向对方展示。

把退出区分为：建立关系、暂时没空、暂未找到合适的人、体验不佳、安全问题、未知。对成功退出表示祝福，不用焦虑文案挽留；用户不说明原因也能离开。

## 14. 数据指标、漏斗与复盘

### 14.1 北极星与早期替代指标

**长期北极星：每期产生的、在提案发出后 14 天内由双方独立确认发生过的见面对数。** 同一期同一对只计一次，不把多次见面累加成多段成功连接。

见面反馈会缺失，因此同时报告三类结果：双方确认见面、仅一方报告见面、未知。不能把未知直接算成没有见面，也不能为得到数据强迫回应。

早期用“有效双向连接对数”作为领先指标：双方同意后七天内，双方至少各发送一条非系统消息。它只是最低互动代理指标，是否有意义仍需要独立反馈判断。

### 14.2 指标口径

| 指标 | 分子 / 分母或定义 | 用途 |
| --- | --- | --- |
| 核验转化率 | 完成核验的去重用户 / 发起注册的去重用户 | 发现资格与邮件流程阻碍 |
| 资料完成率 | 必要资料完整用户 / 完成核验用户 | 检查问卷负担 |
| 本期参与率 | 主动报名本期且符合条件用户 / 本期有资格报名用户 | 衡量真实需求 |
| 候选存在覆盖率 | 至少有一个双向兼容候选的参与者 / 有效参与者 | 判断池子结构 |
| 提案覆盖率 | 实际收到候选提案的去重用户 / 有效参与者 | 判断整体可分配能力 |
| 双向确认率 | 双方同意的候选提案对数 / 发出的候选提案对数 | 判断推荐与表达 |
| 有效连接率 | 有效双向连接对数 / 双方同意的对数 | 判断聊天启动 |
| 确认见面率 | 双方确认见面对数 / 有效双向连接对数 | 判断线下转化，附反馈覆盖率 |
| 下期主动参与率 | 选择下一期的用户 / 仍有约会需求且被邀请选择的用户 | 判断持续价值，注明未知需求人数 |
| 有效获客成本 | 渠道花费 / 该渠道新增首次有效参与用户 | 衡量引流质量 |
| 每次确认见面成本 | 当期列明范围的总花费 / 双方确认见面对数 | 衡量实际交付成本 |
| 安全护栏 | 举报率、严重事件、处理时长、撤回失败、退出障碍 | 限制增长的代价 |

所有比率都带人数、观察窗口与批次，不只报百分比。投诉增多可能来自入口变易用，应结合事件严重程度和未处理工单判断，不能压低举报数量来美化指标。

### 14.3 一份完整漏斗示例

以下仅用于统一单位，**不是业务预测**。假设无补配、无重复用户，每人本期最多一个候选提案：

| 环节 | 示例值 | 正确解读 |
| --- | --- | --- |
| 去重落地访问 | 1,000 人 | 尚不能判断需求质量 |
| 完成核验 | 200 人 | 核验用户占访问者 20%；此处不是注册核验转化率 |
| 完成资料并主动报名 | 160 人 | 有效参与用户 |
| 实际获得候选提案 | 120 人，组成 60 对 | 提案覆盖率 75% |
| 双方同意 | 30 对，60 人 | 双向确认率 50% |
| 有效双向连接 | 24 对 | 有效连接率 80% |
| 双方确认实际见面 | 12 对 | 相对有效连接为 50% |

若本轮列明范围的花费为 4,800 元，且 160 人都是新增有效参与者，则有效获客成本为 30 元/人，确认见面成本为 400 元/对。不能用“60 人互相同意”说成“60 对匹配成功”。

补配上线后，提案数可能增加：用户指标按用户去重、连接指标按双方组合去重，并分别报告首配与补配结果，防止通过反复发提案提高表面覆盖。

## 15. 实验清单与放量依据

### 15.1 第一轮建议实验

| 优先级 | 假设 | 最小试验 | 主要评价 | 防止误判 |
| --- | --- | --- | --- | --- |
| 1 | 用户理解并愿意参加 Dating | 两版真实招募页，小范围访谈与报名 | 有效参与和意图理解 | 不用模糊交友文案骗高转化 |
| 2 | 无照片能跑通闭环 | 首两期无照片服务 | 双向确认、交流、见面与退出原因 | 不只看注册增加 |
| 3 | 双语是关键价值 | 全流程中英文可用性测试 | 核验与问卷完成、提案理解 | 不把翻译差异当成用户差异 |
| 4 | 传单比泛内容更精准 | 相近预算测试获准点位与内容渠道 | 有效参与成本、候选覆盖 | 去重跨渠道用户 |
| 5 | 每周一次的等待可接受 | 连续四期主动报名 | 等待流失、重复参与、反馈 | 排除假期和考试的影响 |
| 6 | 见面卡片能帮助推进 | 双向连接后提供可选卡片 | 实际安排、双方确认见面 | 不降低退出自由 |
| 7 | 可选照片解决主要流失 | 在后续独立批次试验、明确规则 | 全漏斗及安全反馈 | 图片组与无图组人群自选择存在偏差 |

### 15.2 小池子中的实验原则

匹配网络有相互影响：改变一个人的规则也会改变另一人的机会。界面文案可做用户级对比，匹配规则宜按明确批次试验，记录不同批次的供给、时点和渠道差异。

首期不要同时测试十件事，也不要在同一对用户之间应用互相冲突的隐私规则。样本小时将结果标为方向性证据；扩大样本前先预设最小有意义改善、观察窗口和停止条件。

### 15.3 建议的阶段门槛

| 阶段 | 建议进入条件 |
| --- | --- |
| 开始真实内测 | 核验、双语说明、双方确认、退出及举报闭环可用 |
| 做 72 小时集中招募 | 已跑完一轮小规模服务；客服能承接；可分配覆盖达到试验门槛 |
| 连续加大招募 | 连续两期提案覆盖至少 70%，且确认、交流、反馈未明显恶化，无未处理的严重问题 |
| 增加照片 | 访谈和实际流失共同显示照片缺失是主要阻碍，已有访问和审核能力 |
| 增加付费渠道 | 类目与链路获准；自然渠道漏斗已能测量；有明确成本上限 |
| 扩到更多学校 | 清北连续四期能稳定交付；新学校自身有核验、渠道和候选密度 |

这些是首轮管理建议，不能代替统计结论。增长需要同时看质量与容量，不是达成一个数字就自动开放。

| --- | --- | --- |
| 产品与技术负责人 | 报名、核验、匹配状态、权限、可靠性、数据统计 | 技术修复与必要配置权限 |
| 增长与校园合作负责人 | 大使、渠道、内容、物料、来源码、成本 | 聚合渠道数据，不默认看私密问卷 |

### 16.3 用服务产能决定报名上限

示例：若首期有 60 个有效参与者，其中 20 人需要人工核验、每人 5 分钟；形成 30 对候选、每对复核 4 分钟；15 个支持个案、每个 8 分钟，已有约 340 分钟工作，还未包括活动、内容、工程值班和复杂安全个案。

上线前用试运营的真实耗时替换上述假设，为复杂个案留出容量。超过能力时用清楚的候补政策控量，不把全部资料交给未经培训的大使处理。

## 17. 前 90 天路线图

| 阶段 | 重点 | 交付 | 决策依据 |
| --- | --- | --- | --- |
| 第 1–2 周 | 用户研究与最短闭环 | 定位、双语原型、必要功能盘点、12–18 次访谈 | 用户是否理解并愿意参加 |
| 第 3–4 周 | 40–60 人受控内测 | 两期试运营、服务蓝图、候选不足原因 | 无照片是否能产生真实交流 |
| 第 5–6 周 | 小范围 72 小时集中招募 | 双语素材包、传单试验、真实渠道协作 | 有效参与成本、提案覆盖、承接能力 |
| 第 7–8 周 | 修复最大漏点 | 优化问卷、提醒、补配或见面安排中的一项 | 主要问题是获客、兼容还是交流推进 |
| 第 9–10 周 | 提高稳定性 | 自动化重复工作、学校核验完善、可选照片研究 | 人工成本与用户体验是否改善 |
| 第 11–12 周 | 评估持续运营及收费意愿 | 四期趋势复盘、成本模型、小额服务付费研究 | 用户是否获得价值、现金模型是否合理 |

**推荐增长顺序：** 一个有组织能力的种子圈层 → 两校中兼容的国际化圈层 → 认同多元文化的其他清北学生 → 有独立渠道与密度的新学校。

如果只有一所学校已有可用资格核验，另一校只能先做明确标注的候补招募。正式匹配宣传应如实说明当期覆盖，不能让“清北定位”掩盖能力差异。

## 18. 商业模式与长期价值

### 18.1 初期收费建议

前四期建议核心匹配免费，先验证用户是否愿意填真实资料、回应和见面。免费只是首期价格策略，不要永久承诺，未来收费前充分说明。

可优先测试的收入来源：

| 模式 | 提供的明确价值 | 何时考虑 | 主要取舍 |
| --- | --- | --- | --- |
| 自愿线下活动票 | 场地、主持、材料与组织服务 | 有稳定活动需求后 | 规则、取消与退款清楚 |
| 透明的合作场所优惠 | 用户自主选择的咖啡或活动权益 | 有真实见面需求后 | 披露合作，不暴露关系资料给商家 |
| 有明确增值的订阅 | 可选活动权益、额外规划工具等 | 多期留存与付费研究后 | 不能损害基础匹配的公平与安全 |
| 用户明确委托的人工介绍服务 | 更多人工了解与安排 | 团队有专业产能且需求成立后 | 成本高，需明确服务内容和边界 |

不建议首期出售“谁喜欢你”、强迫付费解锁双方已同意的联系方式、按国籍学校售卖对象、卖隐私数据，或把安全能力设为付费项。用户付费不能购买他人的回应或同意。

### 18.2 商业验证顺序

先证明有人愿意来，再证明能交付连接，然后衡量完整服务成本，最后测试愿不愿为明确增值付费。访谈里的付费意愿只能作为假设，实际自愿购买才是更强证据。

不要把所有退出当作收入损失：用户建立关系后离开，是产品可以自豪的成功。学期新生、交换周期和真实推荐可形成新的需求，但不能在没有数据时据此夸大长期收入。

### 18.3 可积累的优势

- 对清北具体用户和跨文化沟通困难的理解。
- 长期可信的校园合作与口碑。
- 可稳定交付的一期匹配流程和异常处理经验。
- 在最少必要数据下改善推荐与交流的能力。
- 用户对隐私、退出和独立团队透明度的信任。

长期资产应是被信任的服务能力，而不是无限积累的私人关系档案。

## 19. 隐私、信任与安全运营

### 19.1 设计要求

以下是本产品建议采用的保护措施；具体法律适用与上线手续应根据运营主体、部署和服务实际确认。

- 用户可预览候选人会看到什么，默认没有公开可搜索人员目录。
- Dating 偏好、聊天和照片按高敏感度处理，访问最小化并可审计。
- 不通过浏览行为、姓名或照片推断国籍、性取向或其他私密属性。
- 不向第三方模型发送可直接识别的完整关系档案作为默认工作方式；需要外部处理时单独评估用途和数据范围。
- 对外通知采用中性措辞，锁屏或邮件标题不暴露约会对象、关系偏好或照片。
- 用户可以暂停推荐、撤回授权、拉黑、举报、请求删除；退出不附带邀请或问卷要求。
- 学校身份核验是门槛，不作为平台承诺人身安全或人品可靠的证据。

涉及个人信息时，应有明确目的、最小必要范围、清晰告知和适当保存期限；敏感个人信息处理涉及额外要求，跨境服务商也需单独评估。相关规则以[《个人信息保护法》](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)为核对依据。

### 19.2 留存与删除策略

上线前为每类数据确定并告知期限，而不是统一写“永久保存”或“注销后全部立即消失”。

| 数据 | 建议原则 |
| --- | --- |
| 人工核验材料 | 尽量避免保存完整证件；采用可遮盖、可低留存的方式，只保留必要核验结论 |
| 用户资料和偏好 | 仅在用户授权服务期间保留，支持修改、撤回和注销 |
| 匹配和聊天 | 明确产品所需期限和删除边界，说明对方已保存内容不受平台控制 |
| 举报证据 | 与普通运营数据分离，仅限必要人员、目的和期限 |
| 统计数据 | 优先汇总，避免可回溯个人的细分报表对外传播 |
| 备份与日志 | 有实际可执行的过期清理机制，不把原始问卷和聊天默认写入日志 |

### 19.3 举报处理与支持能力

建议在公开服务时间内：普通问题一个工作日内首次回应，高风险举报优先人工处理；立即提供自助拉黑及停止联系。具体响应承诺必须与实际值班一致，不能由小团队承诺全天即时救援。

高风险个案包括威胁、持续骚扰、冒充、疑似未成年、未经同意传播隐私等。处理流程为：阻断继续接触、保全必要证据、限制账号或下线内容、人工复核、给受影响用户说明、提供申诉入口。涉及紧急现实危险时提示使用当地紧急求助渠道。

公共反馈只说明处理机制，不披露举报者、匹配名单或私密细节。限制措施记录原因和权限，重大争议尽量由另一位负责人复核。

## 20. 主要风险及调整方案

| 风险 | 早期信号 | 优先动作 |
| --- | --- | --- |
| 定位过窄，候选不足 | 总报名增长，但大量人没有双向兼容候选 | 扩大到认同多元文化的清北学生，优化集中排期 |
| 定位模糊，意图不一致 | 大量用户以为只是语言交换或普通交友 | 修改招募表述，分开不同意图池 |
| 无照片吸引注册但妨碍继续 | 资料完成好、确认或见面差，反馈集中提及照片 | 测试自愿私密照片，保留无照片权利 |
| 少数候选被集中需求 | 大量用户指向同一小组人 | 优化整体分配、曝光上限和有针对性的补招 |
| 海外经历被包装成等级 | 用户觉得被筛选或物化 | 调整品牌、规则和大使话术 |
| 小红书链路受限 | 无法通过准入、素材或导流审核 | 停止受限路径，转有许可校园触达，不改名绕过 |
| 跨校与语言阻碍见面 | 已互选但经常无法约时间地点 | 加强语言偏好、校外地点与时间协调 |
| 交换生季节性流失 | 学期结束前参与下降 | 提前确认在校期限，按学期更新活跃状态 |
| 人工服务拖垮团队 | 核验、结果日和举报积压 | 控量、改流程、自动化重复工作 |
| 隐私事故或冒充用户 | 撤回失效、异常访问、可信举报 | 暂停相关功能与扩散，修复并通知受影响用户 |
| 付费导致信任下降 | 用户觉得被迫花钱才能结束或保护自己 | 保留基础连接、拒绝、退出和安全能力 |

- [ ] 完成 12–18 次访谈与原型任务测试。
- [ ] 邀请共创者自愿参加首轮；目标组织 40–60 名有效参与者。
- [ ] 跑通一次完整匹配与反馈，记录候选不足原因。
- [ ] 获得实际点位及社群发布许可。
- [ ] 达到承接条件后执行 72 小时集中招募。

### 第四步：每期交付后决定下一步

- [ ] 看有效参与，不只看注册。
- [ ] 看双向兼容和实际分配，不只看人群总量。
- [ ] 看有无真实交流与见面，并注明反馈缺失。
- [ ] 核对每条渠道的现金成本和团队耗时。
- [ ] 优先解决最大的一个漏点，再继续加量。

**首月最值得验证的问题：一批真实的清北学生，是否愿意在不公开照片、关系意图清楚、双方同意的情况下，认识并见到一个合适的人。**

### 22.3 用户常见问题

**这是清华或北大官方平台吗？**  
不是。Soulink 由独立团队运营，学校名称用于说明服务人群。只有取得正式授权后才能使用相应合作表述。

**一定要有海外经历吗？**  
海外经历是初期重点触达的共同背景，不是判断用户价值的条件。首期开放范围以报名页说明为准，建议欢迎认同多元文化的清北在校成年学生。

**不传照片还能匹配吗？**  
可以。首期以关系期待、兴趣、语言和时间等信息介绍候选。双方都愿意后，可以自主决定是否分享照片。

**别人会知道我拒绝了吗？**  
不向对方透露单方选择或具体原因。未形成双向意愿时，提案以中性状态结束。

**我只想找普通朋友，可以参加吗？**  
Dating 需要双方都有约会意愿。纯交友活动如开放，会有独立说明和报名，不与 Dating 池默认混合。

**报名后一定能匹配成功吗？**  
不能保证。系统需要双方条件兼容且愿意参加。没有合适候选时会明确告知，由你决定是否下期再来。

**学生身份核验就能保证安全吗？**  
核验仅确认说明范围内的资格，不保证个人行为。平台提供站内交流、拉黑、举报和公共场所见面建议。

**我的资料会给运营或 AI 看吗？**  
应以实际隐私说明为准。首期如有人工辅助或外部模型处理，需要提前讲清哪些数据、为什么使用、谁能访问，不能用“智能匹配”隐藏人工查看。

**找到合适的人后怎么办？**  
可以暂停新匹配或注销，不需要完成额外邀请任务。已经建立的联系如何保留，以双方意愿和产品提供的选择为准。
