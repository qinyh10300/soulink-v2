# SouLink 工作台布局与移动端 UX 规范

## 1. 目标

SouLink 的核心界面采用“主导航 / 任务内容 / 上下文”的工作台模型。桌面端允许用户按当前任务自由分配空间；移动端按任务流重新组织内容，不压缩桌面三栏。

本规范遵循三个原则：

1. 默认状态保持当前 PC 端的视觉比例，不让已有用户重新学习布局。
2. 所有面板都可以通过拖动、按钮或键盘折叠，并始终保留明确的恢复入口。
3. 移动端只显示当前最重要的任务，上下文内容通过抽屉、切换或独立页面进入。

## 2. 参考方案

- [VS Code Custom Layout](https://code.visualstudio.com/docs/configure/custom-layout)：Primary Sidebar、Editor、Secondary Sidebar 的工作台结构；面板可隐藏、恢复，布局状态会被记住。
- [VS Code User Interface](https://code.visualstudio.com/docs/editing/userinterface)：侧栏边界可拖动，布局切换后保留用户状态。
- [Fluent 2 Layout](https://fluent2.microsoft.design/layout)：区分 responsive 与 adaptive；小屏不只缩放，还应隐藏、移动或重新编排信息。
- [Fluent 2 Drawer](https://fluent2.microsoft.design/components/web/react/core/drawer/usage)：主导航通常从左侧出现，辅助信息通常从右侧出现；窄屏适合临时抽屉。
- [WAI-ARIA Window Splitter](https://www.w3.org/WAI/ARIA/apg/patterns/windowsplitter/)：拖动分隔条使用 `separator` 语义，并支持方向键、Home、End 与 Enter。
- [Apple Human Interface Guidelines: Split Views](https://developer.apple.com/design/human-interface-guidelines/split-views)：多栏分别承担 primary、supplementary、detail 层级，并保持分隔位置清晰。
- [react-resizable-panels](https://github.com/bvaughn/react-resizable-panels)：成熟的 React 分栏实现，提供折叠、像素/比例尺寸、持久化及键盘可访问性。

## 3. 桌面工作台

### 3.1 全局主侧栏

适用宽度：`>= 1024px`。

| 属性 | 规则 |
| --- | --- |
| 默认宽度 | `244px`，与现有页面一致 |
| 最小展开宽度 | `208px` |
| 最大宽度 | `336px` |
| 折叠宽度 | `0px` |
| 吸附行为 | 向左拖过最小宽度后折叠 |
| 恢复方式 | 左侧边缘按钮；展开导航快捷键按钮 |
| 状态保存 | 本地保存最近一次展开宽度与折叠状态 |

侧栏展开时保留完整品牌、导航、最近意图与账户区。折叠后不保留永久图标轨道，避免占用工作空间；仅显示不遮挡内容的边缘恢复按钮。

### 3.2 首页任务区与上下文区

适用宽度：`>= 1280px`。`1024px - 1279px` 保持原有单主栏状态。

| 面板 | 默认 | 最小展开 | 最大 | 可折叠 |
| --- | --- | --- | --- | --- |
| SouLink 助手 | 剩余空间 | `520px` | 不限制 | 是 |
| 你的上下文 | `320px` | `280px` | `440px` | 是 |

任一面板折叠后，另一面板占满当前工作区。左右边缘分别保留恢复按钮。至少一个任务面板必须保持可见；不会出现没有恢复入口的空白页面。

### 3.3 拖动条

- 视觉线宽 `1px`，交互热区至少 `10px`。
- 默认只显示低对比度分隔线；悬停、拖动与键盘聚焦时显示握柄和品牌绿色强调。
- 鼠标指针使用 `col-resize`，拖动时禁止文本选择。
- 双击恢复该组默认比例。
- 支持键盘方向键调整，Home/End 到达边界，Enter 折叠或展开。
- 按钮都包含 `aria-label` 与 tooltip，不依赖图标猜测含义。

### 3.4 状态记忆

- 全局侧栏和页面内分栏分别保存，互不覆盖。
- 只在对应断点恢复布局，桌面布局数据不参与移动端计算。
- 数据异常、窗口太窄或版本升级时自动回退到默认值。
- 提供“恢复默认布局”命令，避免用户卡在不适合的历史尺寸。

## 4. 移动端适配

### 4.1 断点

| 范围 | 布局 |
| --- | --- |
| `< 640px` | 手机单栏，底部主导航，顶部页面动作 |
| `640px - 1023px` | 平板单栏或列表/详情两段式，不显示桌面拖动条 |
| `>= 1024px` | 桌面工作台 |

### 4.2 页面规则

- 首页：只保留助手主任务；上下文摘要通过页面内入口进入，不显示被压缩的右栏。
- 消息：会话列表与聊天详情在手机上分步显示，返回动作明确；群资料使用全屏抽屉。
- 树洞：帖子流单栏；筛选和发布操作固定在易触达区域；回复不产生横向溢出。
- 时间表：手机优先日程列表/日视图；创建和邀请使用底部抽屉或全屏表单。
- 个人主页与意图详情：信息卡、时间表和操作区按阅读顺序纵向排列；关键动作保持可见。

移动端所有页面必须考虑 `safe-area-inset-*`、动态视口 `dvh`、屏幕键盘和至少 `44px` 的主要触控目标。

## 5. 视觉与动效

- 延续当前纸白、炭黑、清华/松绿色的克制配色，不重做 PC 信息层级。
- 动效只用于状态解释：面板展开/折叠 `160-220ms`；遵循 `prefers-reduced-motion`。
- 页面区域不新增装饰性卡片或大圆角容器。分区依靠边界、留白和背景层级。
- 拖动过程中不播放复杂动画，确保指针与面板边界实时同步。

## 6. 验收清单

- 在 `1024px`、`1280px`、`1440px`、`1920px` 下，默认 PC 布局与改造前比例一致。
- 左侧栏、首页主区、首页上下文区均可拖到折叠，并能通过边缘入口恢复。
- 刷新后恢复上一次桌面布局；恢复默认后回到 `244px + 自适应 + 320px`。
- 拖动条可用鼠标和键盘操作，聚焦状态清晰。
- 在 `390x844`、`430x932`、`768x1024` 下无横向滚动、文本遮挡或不可达操作。
- 登录、首页、意图、树洞、消息、群聊、时间表、公开主页的核心流程可完成。

## 7. 可复用的 Web 工作台美学方法

后续新增页面时，优先把界面看成三个层级，而不是一组并列卡片：

1. **方向层（Navigation）**：回答“我在哪里、还能去哪里”，保持稳定，不承载当前任务细节。
2. **任务层（Work）**：回答“我现在要完成什么”，始终获得最多空间和最高视觉权重。
3. **上下文层（Context）**：回答“完成任务还需要参考什么”，允许按需展开、折叠或在移动端临时出现。

每个页面按下面的顺序做交互判断：

1. 先确定用户当前唯一的主任务，再决定主面板。
2. 只有需要持续对照的信息才进入常驻辅助面板；短暂信息使用抽屉或弹层。
3. 桌面空间变化优先交给用户拖动，窄屏变化优先重新编排任务顺序。
4. 所有“消失”都必须可发现地恢复；恢复入口贴近面板消失的边缘。
5. 尺寸、折叠和焦点变化都要保持可预测，并用轻量边界与短动效解释状态。
6. 视觉强调只服务于任务优先级：主动作使用品牌色，其余区域以纸白、边线和留白建立层级。

这套方法适用于消息、日历、资料编辑、匹配结果、后台管理等工作型页面。内容型页面可以减少分栏，但仍应保留“主任务优先、上下文按需出现”的结构。

## 8. 本次实现矩阵

| 区域 | 桌面端 | 移动端 | 状态保存 |
| --- | --- | --- | --- |
| 全局导航 | `>=1024px` 可拖动、折叠、边缘恢复 | 顶栏 + 底部主导航 | 像素宽度与折叠状态 |
| 首页 | `>=1280px` 助手与上下文均可折叠 | 助手单任务视图 | 上下文宽度与折叠状态 |
| 意图创建 | `>=1280px` 对话与确认区均可折叠 | 确认区使用移动端 sheet | 确认区宽度与折叠状态 |
| 消息与群聊 | `>=768px` 会话与详情均可折叠 | 列表 / 详情分步导航 | 会话列表宽度与折叠状态 |

已验证视口：`390x844`、`430x932`、`768x1024`、`1024px`、`1280px`、`1440px`、`1920px`。桌面默认比例保持不变；移动端不加载桌面分隔条，也不会读取桌面面板尺寸。
